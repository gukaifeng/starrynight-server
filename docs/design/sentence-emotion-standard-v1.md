# 逐句情感与全身表演标准 v1

2026-10-03。客户端标准权威 JSON 为客户端仓库的 `EmotionPerformanceStandard.json`；本仓库 `services/character_ai/emotion_standard.json` 是审查后显式复制的合约快照，服务端运行不读取客户端路径。标准涵盖 28 种应用情绪、7 种发声风格、7 种拟声，每项 3 个不同身体组合，共 126 个组合。具体角色骨骼与授权资产留在客户端。

## 百炼能力与语义边界

已通过云端只读配置确认实际 TTS 为 `qwen-audio-3.1-tts-flash`，不是仅凭代码默认值猜测。官方支持 23 个文本控制标签和 7 个富语言标签，来源：[实时语音合成：情感与富语言标签](https://help.aliyun.com/zh/model-studio/realtime-tts-user-guide)。23 项中有情绪、发声方式、速度及角色化声线，不能全部称为情绪。应用另有开心、害羞、亲近、思索等语义，这些用自然语言指令表达；不是厂商枚举扩充。普通开心不再一概使用 `[excited]`。

`emotion`、`style`、`delivery`、`vocal_events` 分开保存；厂商方括号只在可信 TTS 适配器加入，不出现在聊天正文。心理是虚构角色的第一人称感受，不是模型推理过程，永不进入语音输入。

## 新客户端协商

请求新增可选 `emotion_contract: 1` 与 `previous_emotion`；未协商客户端沿用原行为。每句一个 beat、明确情绪、至少一条有效可见心声。台词未通过检查前不发布、不计入聊天、不进行 TTS；流式草稿格式失败走已有的有界规划回退，共用原请求预算，不添加逐句模型调用。多句误放一 beat 时，仅在已有 AI 心声覆盖全部句子的情况下拆分，不能编造默认心声补洞。

相邻句包括上一轮最后一句不得同标签。提示词先要求自然的语义转折；发布前再做最近语义邻居归一化，例如 happy/playful、neutral/calm、curious/thoughtful、angry/serious，避免为了去重随机转为完全相反的情绪。历史按认证 owner + character 隔离，不信任客户端声称的账户；数据库最近标签优先于请求中的兼容提示。

预生成候选的上下文键加入标准版本，退休尚未说出的旧草稿，不删历史音频。消费时检查相邻标签；保留 `voice_emotion` 标明缓存 PCM 原合成标签，表现标签仅在语义相近的状态间调整，不声称修改了缓存中的声线。消费不会因此重新合成或串行等待新的表演请求。

## 首次问候和同步

48 组现有打包问候补充每句心理和情绪；不修改已合成台词/PCM。注册接口记录相同元数据和末句情绪。新客户端的固定问候覆盖表兼容旧 OSS 包。

直播每个 beat 的首 PCM 开始即驱动标准表演，文字、心声先于音频公开；后续表演生成仍可并行补充。拟声可带 `at` 分数，在语义停顿边界插入 TTS 控制标签。表演的强度/时间以当前语句时长控制，独立发声风格作为同一表演的修饰，拟声作为短时叠加，避免笑声硬切断整段身体动作。

固定问候只有整段 PCM，句子 `at` 是按文本长度估计的进度，不是供应商音素级时间戳。普通逐句音频的句子起点有真实 PCM 回调；拟声非零位置与旧整段问候的内部位置属于近似同步。静音时仍用句子时间线播放表现，不等待扬声器。
