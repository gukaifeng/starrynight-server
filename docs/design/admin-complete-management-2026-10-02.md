# 星夜服务器完整管理工作区

本次扩展在既有控制室中补齐服务器业务、文件与维护功能，沿用独立 HTTPS 8444、Go 管理进程和 React / Headless UI / Tailwind。机器监控继续由服务器厂商提供；本次不修改 SSH。App 的 HTTPS 8443、账户、会话协议和付费模型配置保持兼容。

## 功能覆盖

| 工作区 | 实际数据与操作 |
| --- | --- |
| 原有业务管理 | PostgreSQL 全部 23 类应用表；用户、资料、头像、设置、偏好、作者、角色、订阅、关注、会话、消息、记忆文档、目标、资源发布、反馈、账户同步、迁移、管理员与审计 |
| 原有 AI 管理 | 12 类 SQLite 持久化表及角色设定、完整提示词、模型与预算；查看编排、语音设计、用量、反应与接话预缓存，按业务白名单编辑或清理 |
| 资源与模型 | 私有服务器资源上传、角色关联、说明、校验、下载、回收与恢复；私有 OSS 分页、对象信息、上传、下载与删除保护；嵌入式 GLB / VRM / FBX 网页预览、骨骼、原始动画和 Morph 形态检查；图片预览；嵌套推理模型文件只读 |

| 备份与恢复 | 历史快照清单、受保护下载；一致业务备份、文件哈希 / SQLite / 归档校验；保护备份、独立 PG 候选库、切换与失败回退；备份回收及恢复 |

“全部可视化”指服务器持有的业务及运行资源都具有对应工作区，不代表允许任意改写内部收据、审计、付费账本或不可变发布内容。这些内容保持可查、业务动作有界。密钥、密码哈希、私钥、会话令牌不提供明文查看。

## 权限与一致性

新增服务器管理能力仅供 owner；下级编辑者与观察者继续使用已有业务权限。下载与试听均走已认证同源代理，不把 OSS 长期凭据、AI 管理令牌交给网页。上传最大 512 MiB，只有完成认证的指定上传路径获得该限额。模型引用外部文件时拒绝自动加载，避免预览资源引入第三方请求；建议上传嵌入贴图的完整 GLB。

Redis 键名使用 AES-GCM 不透明操作句柄，列表中登录会话以短哈希显示。正文递归隐藏 JSON 凭据；大于 2 MiB 的键不读取完整正文或通过此入口删除。使用 SCAN，不执行 KEYS 或 FLUSHALL。变化中的缓存拒绝旧版本删除。

本地配置与资源写入使用文件锁和版本检查；长任务持独占维护锁，管理端写入暂时拒绝。普通 App 只在创建完整快照、恢复或明确重启服务时短暂受影响。不可变 OSS 发布与对象删除共用 PostgreSQL advisory lock，跨 API 节点和 CLI 发布串行，防止“检查未引用后刚被发布”竞态。上传使用官方 OSS SDK 的禁止覆盖标志。

## 备份与恢复语义

新完整备份包含 PostgreSQL、在线 SQLite 快照、AI 持久化资源和配置覆盖、服务器资源库及其回收目录、私有基础配置副本。短暂暂停 API / AI 并阻止管理端写入，保证业务快照边界。文件逐一记录 SHA-256；恢复前校验大小、哈希、SQLite 完整性与 tar 路径和类型。

恢复先制作当前保护备份，把目标 PG 导入独立候选库并执行当前向前迁移，验证后再替换。管理员及审计取当前版本，不随业务回到过去；注册序号不回退，备份后分配过的星夜号仍被保留。用户和管理员 session_epoch 提升，旧登录失效。媒体在独立目录解包，当前目录和旧数据库保留，服务就绪失败时退回原数据库与媒体。

Redis 是可重建会话和限流状态，不作为业务权威数据恢复；旧会话不从备份复活。当前证书、凭据和服务入口也不随业务恢复覆盖。旧快照缺少完整恢复清单时只提供查看和现有文件下载，不伪装为完整可恢复快照。

配置先检查当前版本，在独立进程中实际验证 PG / Redis，再保存原配置并原子替换。保留不认识的已有环境字段，为后续版本扩展留空间。应用任务就绪失败时恢复原配置、重启服务；不把错误输出中的连接密码回传网页。

## 模型和声音边界

网页使用 Three.js 的官方加载器检查通用资源及原始动画；VRChat / Unity 专用 shader、控制器和 AssetBundle 不能直接在网页完整复现，最终材质和角色行为仍以 App / Unity 为准。Unity 包保持可下载和查看清单，可另传配套 GLB / FBX 进行网页检查。浏览器预览代码按需加载，不增大普通业务页面首屏脚本。

声音试听只使用现有持久化文件，不调用百炼、不生成新音色。对话音频关联是针对近期 5000 条回复与当前音色的最佳匹配，旧音色产生的散列文件可能只有文件信息，不伪造关联。文件移入回收站后，历史对话对应声音可能暂时无法直接重播，恢复后重新可用。
