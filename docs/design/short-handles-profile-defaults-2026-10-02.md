# 简短星夜号与资料默认值

用户要求星夜号使用小写 `xy` 和注册序号，去掉原来的固定高位数字。迁移 11 将 `XY100000000037` 转为 `xy37`。UUID、账户所有权、会话和角色数据关联均不变，用户仍不能修改星夜号。

## 分配与扩容

新增 PostgreSQL `starry_registration_sequence`，注册直接使用数据库列默认值 `xy || nextval(...)`，不在 Go 实例、Redis 或客户端计算。所有 API 节点连接同一权威数据库写入入口；两个独立连接池并发分配也是一个全局序列。用户表唯一约束和格式约束、`account_handles` 主键及当前别名唯一索引共同保护分配。序列不循环，注销及回滚留下的空号不复用；注册序号是分配顺序，不能解释成现存用户数量或严格提交先后。

多 API 节点可直接扩容；未来数据库分片或多独立写主库必须保持统一号码分配入口，不能把同一个序列各复制一份独立发号。该实现不声称解决未部署的跨数据库多主分配。认证继续使用 UUID 和可撤销会话，公开序号不是认证凭证。

迁移锁定用户及别名表，保留旧长号为退役别名、建立新短号。新序列从旧序列的已分配位置减去固定基数初始化，包含已注销、未提交等消耗的位置，不按当前用户数重新编号。使用新序列避免 `setval` 不回滚造成旧在线分配器被改坏；若迁移失败，新序列随创建事务撤销。旧分配器保留为历史依据，不再用于新用户。Down 明确拒绝破坏性退回，未来改号走保留别名的前向迁移。

## 资料

新用户固定简介为“在星夜，遇见温柔。”，默认头像为 `starry-orbit-v1`。已有自定义简介、照片保留；缺失简介补默认值，猫/兔默认头像统一为保留的小星球。新作者初始简介也使用同一默认句，客户端个人主页和编辑资料读取同一个账户 `profile.bio`，不再用作者宣传句填补用户简介。

AI 默认称呼仍在账户 settings 的 `default_nickname`，角色专属称呼仍在角色偏好中，解析顺序不变。客户端集中编辑沿用现有版本化账户同步，不新增重复存储。

## 验证

Go vet/race、构建和真实 PG/Redis 全部集成测试通过。新增迁移测试在独立 schema 从版本 10 升级到 11，验证 UUID 和自定义简介保留、默认头像替换、旧号保留以及分配器不倒退；新增并发测试通过两个独立连接池创建 24 个账户，全部号码唯一。

测试隔离的两次问题已修复：pgx `ConnString()` 不序列化后改的 RuntimeParams，现改为显式 DSN `search_path` 并检查 `current_schema()`；隔离 schema 必须包含 public 以找到 `pg_trgm` 运算符，同时显式指定 Goose 版本表所在 schema，避免误用主测试 schema 的版本表。最终完整重跑通过，临时测试 PG/Redis已停止，不恢复 Mac 业务服务。
