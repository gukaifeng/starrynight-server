# 星夜控制室

管理平台、管理 API 与部署均属于此独立服务端仓库。入口为独立 HTTPS 8444，原 App 的 8443 不变。

## 设计决定

使用者是星夜运营者与开发者；页面的任务是理解角色、账户和推理服务的真实状态，并完成可追踪的修改。

颜色：轨道深蓝 `#142c3f`，雾蓝背景 `#e9f0f1`，月白工作区 `#fffdf8`，潮水青 `#57939a`，暮红危险操作 `#c37f68`，星图灰蓝 `#a3baca`。

字体：Fraunces / 宋体用于少量标题；IBM Plex Sans / 苹方用于正文；IBM Plex Mono 用于 ID 和时间。字体打包，不依赖第三方字体网站。

布局比较：全屏卡片墙易浏览角色但不适合密集管理；采用导航、列表、详情三栏，移动设备改成详情抽屉。

```
导航       内容标题 / 搜索 / 新建
           紧凑数据列表       详情与编辑
服务状态   分页               保存 / 业务操作
```

标志性元素是服务星图：入口、账户、推理与缓存的连线对应真实依赖与探针结果。其余区域保持安静，避免把管理台做成指标大屏或营销首页。初稿审查移除了装饰性 KPI 巨字与无意义编号，保留数据表与实际操作。

## 边界与鉴权

独立 Go 管理进程仅绑定 loopback，由 Caddy 8444 代理。SCS Redis 保存独立 HttpOnly / Secure / SameSite Strict 管理会话，管理员密码使用现有 Argon2id。每次请求验证管理员启用状态与 session_epoch；角色为 owner / editor / viewer。App 账户令牌不能登录管理端。

修改要求精确同源 Origin 与会话 CSRF token；登录限流分布式存 Redis。SQL 表和字段来自固定注册表，所有查询值参数化；不提供任意 SQL、命令执行、访问令牌或密码哈希查看。写操作先记意图，成功或失败再记结果，日志只保存操作目标，不记录密码和聊天正文。

账户业务编辑复用 Store 的 CAS 与同步事件；角色官方目录编辑独立验证、递增版本。内部变更流、重置收据、付费调用账本与审计只读，不能当作普通行任意修改。删除或重置要求二次确认。AI 管理通过私有 worker 管理接口，浏览器不接触供应商密钥。

## 交付与扩展

新增资源在管理注册表中描述主键、字段、编辑能力和业务动作；前端据此形成统一工作区。AI 角色设定的覆盖保存于 worker 持久化 records，可恢复出厂设定；运行配置采用白名单校验并原子持久化。服务重启只允许预先列出的 systemd 单元。

管理账号由专用 bootstrap 命令从 stdin 创建，首个 owner 不使用默认密码。发布目录包含编译后的前端与独立管理二进制；凭证、数据库、抓图留在 .local，公共仓库不含私有运行内容。

技术参考：[React](https://react.dev/learn)、[Headless UI](https://headlessui.com/react/dialog)、[Tailwind Vite](https://tailwindcss.com/docs/installation/using-vite)。
