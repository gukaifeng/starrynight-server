# 对话失败恢复与传输一致性

## 已确认的失败来源

云端 Shinano 最近失败的一轮耗时 11.422 秒，trace 的最终错误为 `STRUCTURE_INVALID`。首个流式候选命中重复检测，随后转入角色规划器；规划器两次 HTTP 请求均成功，但 JSON 校验失败。保留的私有 schema_failure 说明，`extra_lines`、`detail`、`visually_visible`、`vocals` 被错误放在根对象。台词、分段、情绪和 goal_feedback 本身能够独立通过验证。这不是设备断网；原始对话、账号及完整捕获没有加入公开仓库。

## 处理与边界

- 仅在服务商内部紧凑规划格式中投影允许字段：根对象和分段里的未知装饰字段省略，可选心理/动作说明按各自类型审查；不补写台词、不截断台词、不修复控制字段混入台词。台词仍由 Dialogue 校验，之后仍做语言、情境、重复及实际动作能力审查。公共账户、请求接口继续拒绝未知字段。
- 未发布的流式 JSON、内容或空回复错误，可以使用既有角色规划器恢复，共享有限生成预算。已发布的合法分段保留；可选尾部错误不重新生成已经说过的话。
- 客户端最多三次传输尝试，复用同一 request_id 和完整请求体。已完成请求直接恢复原结果及缓存音频；已清理的未发布 interrupted 请求允许重试。running 请求不重复启动生成。关闭旧连接的路径仍由 TurnStreams 持有，清理等待单独退避。
- 请求哈希改为递归排序的 JSON，不因对象字段顺序改变而误报编号复用。旧哈希仍可验证，并在成功验证时升级。内容变更仍拒绝。
- 单 worker 启动时将无结果的残留 running 请求标记为 interrupted；仅生命周期启动执行，管理员读取 Store 不触发恢复。这一步不调用模型，已有结果保持不变。未来多个 AI worker 共用存储需要分布式执行租约，不能直接移植这一启动假设。
- 错误传输保留服务商码中的小数点，例如权限/欠费错误不会降级成泛泛的网络中断。客户端区分离线、超时、连接断开、数据格式异常、认证、繁忙及服务商权限错误。可恢复错误先重试，最终失败才标记用户气泡。

重试次数有限，避免持续生成或无限消耗。一次中断的上游调用仍可能计费；同编号的**已完成结果恢复**不再调用模型，不能据此声称所有网络重试均不计费。权限、欠费和持续服务故障仍可能最终失败，必须准确说明，不能伪装成用户断网。
