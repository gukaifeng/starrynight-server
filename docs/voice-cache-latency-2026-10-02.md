# 青柠预缓存延迟诊断与共用链路修复

## 实际证据

通过已授权 SSH 读取云端私有追踪，并从已配对 iPhone 的 App 数据容器只复制耗时文件，对照同一追踪 ID。原始记录仅保存在忽略的 `.local/logs/lime-*.json`，不提交账户、对话或凭证。

| 青柠请求 | 服务端文字准备好 | 服务端首 PCM 交付 | 手机首次输出 | 结果 |
|---|---:|---:|---:|---|
| 19:42:11 的接话 | 13.746 s | 14.060 s | 14.573 s | 接管仍在生成的候选 |
| 另一条接话 | 33.084 s | 33.469 s | 页面已隐藏，仅缓存 | 接管仍在生成的候选 |
| 19:44:00 的接话 | 118.840 ms | 121.140 ms | 728.846 ms | 完整缓存 |
| 19:44:28 的接话 | 265.834 ms | 268.936 ms | 893.254 ms | 完整缓存 |

14 秒候选的后台任务没有排队，但发生两次结构调用（4.201 s + 5.047 s）及一次内容修订（4.175 s）；TTS 总生成 634 ms、音频长度 4.640 s。另一条候选先排队 9.190 s，随后发生 9.489 s、18.957 s 和 4.038 s 的模型请求，后台总计 43.425 s。前台在其尚未完成时接管，仍等待约 33 秒。

这证明主要问题是预生成的排队和重复模型调用。URLSession 的“接收响应流”是整个流的持续时间，包含服务器在两个事件间生成/等待，不代表连续传输音频用了 14 秒。完整缓存的几次手机实际在约 0.5～0.9 秒首次输出；完整播放耗时属于句子长度。

## 修改

- 保留角色对话使用 `qwen-plus-character`，把非台词的表演控制路由到独立 `performance_model`，默认沿用已在项目使用的 `qwen-turbo`，关闭思考；可在管理平台配置。减少表演与核心台词争用慢模型。
- 四个后台核心槽位中，低优先级场景最多占两个，给接话保留空间；真实选择可把同一个队列任务升级，最多额外一个前台槽，不新开一份生成。选择后立即取消未选择的两个仍运行候选，仍保留一次性消费和账号隔离。
- PCM 完整缓存后立即标为 ready 并释放核心槽位，后续可选表演仍可补充。前台可接管已经有 PCM 的流，先交付音频，保留后续表演，不能因表演未结束继续把它标为“核心仍生成”。
- 提示词明确完整 `goal_feedback` 示例。仅当缺少关系进度控制字段时补保守零值与当前用户的原文证据，严格 schema 继续检查；不补造台词、不提升关系、不吞掉非法值，不因这种遗漏再调用一次付费角色模型。
- 低置信度的同主题检索不再触发整轮重写；明确的逐字/近似复制和高置信中文语义仍检查。部署的 BGE 是中文模型，不再用它对纯英文打分；英语仍走账户级逐字/近似复制检查，不声称保证任意语义等价检测。本轮历史检查记录是每账户的最后一次，不能据它判定 14 秒候选的具体内容修订理由；排队、结构修订和多次生成的时间由对应 trace 直接证实。
- 可选心理描写的重复/无效内容按现有编译规则过滤，避免重写已合格的台词。没有本地捏造替代心声；错误语言、错误手势和复制台词仍走内部修订。
- 客户端将“已就绪缓存”和“接管未完成的预生成”分别显示；响应流阶段的名称注明包含生成等待，防止把它误判为下载速度。

缓存未完成时仍接续同一生成，这是既有用户要求。修复不能承诺还未生成出的新内容瞬间出现；应分别验证缓存已就绪、接管运行中、完全冷请求。

依据 [百炼 Character 官方文档](https://www.alibabacloud.com/help/en/model-studio/role-play) 与 [结构化输出官方文档](https://www.alibabacloud.com/help/en/model-studio/qwen-structured-output) 保留 JSON 与会话缓存协议，没有把 JSON Object 当作保证全部 schema 合格的强约束。

## 验证

Python 258 passed / 4 skipped，新增覆盖保留接话槽位、选中任务提升、取消计数、PCM 就绪先于表演、缺失进度控制不重写、英文不使用中文嵌入、可选心声不触发重复付费生成。逐字重复仍必须拒绝，高置信中文修订仍通过原测试。旧取消测试固定“四个模型已运行”的断言改为实际只运行两个、取消数与启动数相同、全部槽位释放。
