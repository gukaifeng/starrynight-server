# 控制室记录图片 · 2026-10-02

角色、用户及作者记录现在显示真实图片，便于在管理列表中识别对象。复用已有资源，不调用图片生成模型，不修改账户和角色设定。

## 展示位置

- 角色目录与 AI 角色设定：紧凑圆形头像，详情显示头像和完整封面，点击可放大，Esc、关闭按钮及遮罩空白可返回。
- 用户账户及头像存储：当前账户的上传照片，或与 App 保留的月亮星环默认头像相应的矢量图；上传替换后刷新显示新照片。
- 作者：关联账户头像，官方独立作者使用默认星夜图案。
- 会话、订阅、关注、消息等记录：角色、作者或用户标识旁显示相应头像，详情的关联字段也显示。
- 自建角色：优先查找独立图片，再沿 `runtime_id` 或 `base_id` 查找基础角色；继承最多八层并检测循环。未提供图片的记录明确显示占位。

图片放大保持完整比例，不使用固定宽高拉伸封面。头像保持圆形，窄屏详情和放大窗口复用相同样式。

## 私有资源与接口

新增已认证管理路由 `/admin-api/v1/record-images/{kind}/{id}/{variant}`，kind 为 character / user / author，variant 为 avatar / cover。仅在独立 8444 管理服务注册，App 8443 不提供该接口。沿用管理员会话，不把图片改为匿名公开下载。JSON 列表不内嵌二进制，图片单独延迟加载。

用户照片来自 PG `account_avatars`，必须与该账户当前 `upload:<sha256>` 引用匹配。作者从真实 `user_id` 关联账户；默认 SVG 是代码自带矢量图，不调用生成服务。

角色图片存储在 `<runtime>/data/library/record-images/`，由 `manifest.json` 指定 `objects/<sha256>.jpg`。读取校验格式、大小、摘要和 JPEG 尺寸，拒绝路径逃逸及符号链接。数据库中的任意网络地址不会被网页或服务端自动抓取。图片属于私有资源库，现有完整备份和恢复覆盖此目录。

## 显式导入流程

服务器不依赖客户端目录。作者工具通过明确输入导出独立资源包：

```sh
python scripts/export_admin_artwork.py \
  --catalog /explicit/CharacterCatalog.json \
  --covers /explicit/CharacterCoverCatalog.json \
  --asset-root /explicit/Assets.xcassets \
  --asset-root /explicit/other/Assets.xcassets \
  --output .local/admin-artwork
```

使用已有封面、头像及头部范围；头像为 512×512，封面最长边不超过 2048，输出管理用 JPEG 预览，原始资源不变。依赖使用现有 Python 锁文件中的 Pillow。缺图时报告角色 ID 并返回失败，不用其他角色图片冒充。

部署机运行 `scripts/deploy/install_admin_artwork.py --source <uploaded package> --root <active runtime>`。先逐项验证，再在私有资源目录构建候选文件夹；与管理写入及维护共用文件锁。旧图片包移入保护备份，新包切换失败时恢复旧包。无需发布 App 或修改业务数据库。
